① Single purpose description
════════════════════════════════════════════
在英文网页上按用户设定的词汇水平标出难词，并在鼠标悬停时给出释义。

所有功能都服务于这一件事：判断哪些词对当前用户算生词，然后解释它们。分级、词典释义、音标全部使用扩展内置的本地词库在本机完成；只有在用户主动点击卡片上的按钮时，才会调用用户自己配置的 AI 服务解释该词在当前句子中的含义。


════════════════════════════════════════════
② storage justification
════════════════════════════════════════════
保存四类本机数据：

1. 用户设置：词汇水平、标注样式、已通过的考试、备考目标、不标注的网站列表。
2. 用户手动标记为「已认识」的单词，之后不再标注它们。
3. 已生成的 AI 释义缓存。缓存是为了同一个词不让用户付第二次费用。
4. 用户自己填写的 API Key。

全部存放在 chrome.storage.local，不使用 sync、不上传到任何服务器，卸载扩展时随之删除。用户可在设置页随时清空，也可导出为 JSON 备份（备份不含 API Key）。


════════════════════════════════════════════
③ activeTab justification
════════════════════════════════════════════
用户点击扩展图标打开弹窗时，弹窗需要两项信息：

1. 向当前标签页的内容脚本询问「本页标注了多少个词」，以显示状态。
2. 读取当前页面的主机名，以显示「在这个网站上标注」的开关，让用户可以针对该站关闭标注。

仅在用户主动点击扩展图标后生效。扩展不会主动访问、遍历或读取任何标签页的内容。


════════════════════════════════════════════
④ Host permission justification
════════════════════════════════════════════
分三类说明：

1. 内容脚本 <all_urls>
核心功能是在用户阅读的任意英文网页上标出难词，因此内容脚本必须能在任意页面运行。脚本只读取页面文本用于本地分词和分级，使用 CSS Custom Highlight API 上色而不修改页面 DOM，不向任何服务器发送页面内容。

2. 十个 AI 服务商 API 域名，以及 localhost 与 127.0.0.1
仅当用户主动点击卡片上的「AI 释义」按钮时，后台脚本才向用户自己选择、并已配置 API Key 的那一家发起请求。这些域名预先声明，是为了避免「用户已存好 Key，请求却被浏览器拦截，而错误只显示连接失败」这类用户无法自查的故障。localhost 与 127.0.0.1 用于用户本机运行的 Ollama，请求不离开用户的机器。

3. 可选权限 https://*/*
仅用于「自定义接口」功能。扩展支持任意 OpenAI 兼容接口（自建服务、代理、未预置的服务商），其地址在发布时无法预知，而 Chrome 要求 permissions.request() 的 origin 必须事先在 optional_host_permissions 中声明。

实际行为：只有当用户在设置页填入接口地址并点击保存时，扩展才调用 permissions.request 申请那一个域，一次只申请一个。用户不使用自定义接口，就永远不会申请任何额外权限。该项只声明 https，非本机的明文 http 地址在申请权限之前即被拒绝。
